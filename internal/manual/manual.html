Offline illustrated guide

Review your recordings with confidence

Track Tagger reads concert notes and FLAC files on your computer, proposes metadata, and gives you a chance to check uncertain matches before anything is written.

Start in Preview. It leaves music unchanged while you inspect the proposals and save corrections. Choose Copy when you want tagged duplicates, or Update originals only when you are ready to change the source files.

Use your browser’s Find command (Ctrl+F on Windows/Linux or Cmd+F on macOS) to find a topic or error message in this guide. Use Print (Ctrl+P or Cmd+P) to print or save it as a PDF for later reading.

1. Install and start

On Windows 10/11 x64, install the x64 release; on Windows 11 ARM64, install the ARM64 release. The per-user installer places the desktop app and track-tagger.exe under %LOCALAPPDATA%\Programs\Track Tagger without an administrator prompt. A matching standalone ZIP contains both executables. Download from this project's GitHub Releases. If Windows warns about an unsigned installer, check the release and its signature status before continuing.

Open Track Tagger from the Start menu. Each launch starts stopped, even after an upgrade. Choose your folders and mode, then press Start; the local browser page opens. The launcher’s Help button opens this offline manual even while processing is stopped. The running browser interface also has a Help link. Closing the browser does not stop processing. Closing the desktop window hides it in the notification area. Use the tray menu to Show, Stop, or Quit.

2. Choose folders and mode

ModeWhat it doesWhen to use it
PreviewReads local files and saves review decisions in application storage. Does not change music.First inspection and review.
Copy to another folderCopies each recording and its accompanying files to a separate destination, then tags eligible FLAC copies. Sources stay byte-identical.Test the result while keeping originals untouched.
Update originalsChanges approved metadata in source FLAC files.After you have checked the plan and have an independent backup.

Choose a music folder containing one recording or a collection. Copy mode needs a separate destination; source and destination cannot overlap. The app stores reviews, history, and recovery data under %APPDATA%\track-tagger. Keep that directory outside the music trees. On a network share, UNC paths select polling automatically; use Use polling for mapped drives that do not report changes reliably. Stop or quit before disconnecting a drive or moving the collection.

Copy and Update originals automatically process eligible recordings after they have been quiet for two minutes. Recordings with ambiguous evidence wait for review. New or changing files may be shown as waiting until they settle.

3. Find a recording

The Recordings page discovers folders first, then validates them one at a time. Progress and library entries update as it works. Open a recording to prioritize it after the current validation finishes. A failed recording does not stop the others.

The default Compact layout uses compact rows and pages of 100 recordings. Search the library, filter by status, and sort with the column controls. Open a recording to see its notes, proposed album details, artwork, and track titles. The page returns here after saving or applying so you can pick the next recording.

Open Settings to choose Compact or Classic. Classic preserves the card library and full-width review layout. This preference is saved only in the browser where you choose it.

4. Review metadata and artwork

In Compact layout, use the sidebar's Album tab for metadata and artwork and its Notes tab for source notes. The track table sits beside the sidebar so you can compare the evidence with each mapping. Classic shows the same review controls in the previous full-width layout.

  1. Read What needs checking and the source notes. Look for conflicting dates, performers, numbering, missing titles, or uncertain artwork.
  2. Confirm artist, album, and concert date. Dates can be a year, year and month, or full date. Use Date unknown when the concert date cannot be established; existing date tags are preserved.
  3. Choose local artwork only when it belongs to this recording. Keep existing artwork is the safe choice when you are unsure.

Track Tagger proposes an album such as YYYY-MM-DD - Venue, City when evidence supports it. It preserves populated tags and artwork unless your reviewed decision explicitly approves replacement. Ambiguous dates are never silently guessed. A recording with a non-FLAC or mixed audio format is playback-only and cannot be tagged.

5. Check track mappings

In Track titles, compare each audio filename with its disc, track number, title, and optional per-track performer. A guest or bonus performer can differ from the album artist. Use the links under What needs checking to jump to a questioned row.

Track Tagger matches conservative file identifiers, such as t01, s1t01, d1t01, and 1-01. It does not shift titles into place by list order. Missing files or titles, duplicate numbers, and unclear continuations need your decision. If the notes and files cannot establish a correct match, leave the recording for further review rather than inventing a title.

6. Save and apply

  1. After checking notes, titles, performers, and artwork, select the approval checkbox.
  2. Press Save review to store the decision. In Copy or Update originals mode, press Save and apply to write immediately.
  3. If a previously saved review is unchanged, use Apply saved review in a writing mode. Changing any field requires approval again. The watcher can also apply an approved saved review after the quiet interval.

If an apply fails after saving, the review remains saved. Reopen the recording, resolve the reported problem, then retry Apply saved review. Completed recordings need an approved change before they are processed again. An old browser form, plan, or review is rejected when its inputs have changed; refresh and review current evidence.

Before writing: Keep an independent backup of important recordings. Metadata edits change whole-file checksums even though Track Tagger verifies that the exact FLAC audio payload is unchanged. Existing checksum documents are not rewritten.

7. Listen while reviewing

Press Play beside a track. The shared player supports pause, seeking, volume, and previous/next. Audio loads only after you press Play and streams from local files without changing them. FLAC, ordinary PCM WAV, MP3, and Ogg files (.ogg, .oga, .opus) can play when the browser supports their codecs. Any recording containing non-FLAC audio is playback-only.

Playback is limited to locally available files in the current recording collection. If a file changes after the page loads, refresh the page before trying it again.

8. History and undo

Open History & undo to see tagging jobs. In Copy or Update originals mode, Undo metadata changes restores the metadata recorded before a job; Preview shows the history but cannot make that change. Undo does not remove copied companion files. It refuses to overwrite later external edits or later tagging jobs, and it pauses automatic tagging of that recording until you review it again.

Keep the application state directory: it contains original metadata, review decisions, job history, copy ownership, and the recovery journal. Uninstalling the Windows app retains %APPDATA%\track-tagger so undo history remains available.

9. Updates and offline use

The Windows launcher checks GitHub for the latest stable release at startup when Check automatically at startup is on. Check for updates runs an on-demand check. The check retrieves public release information; it sends no music paths, audio, settings, or review data. Turn off the startup check for fully offline operation.

When an update is available, read Release notes. Install update asks for confirmation, downloads the matching installer, verifies it against SHA256SUMS, and stops active work safely. The native launcher reopens visibly. If processing was running when it stopped for the update, the launcher resumes with the saved mode, folders, and polling setting, without opening a browser tab. Use Open browser to return to the review page. If processing was stopped or installation failed, the launcher reopens stopped. If resume fails, read the launcher error, correct the settings, and press Start. Portable and development builds open the release page for manual installation.

10. Recovery and safeguards

Track Tagger stages each replacement beside its destination, checks fresh source and destination content, verifies the exact FLAC audio payload, and records journal intent before replacing a file. On an interrupted write, restart with the same folders, mode, and state directory so recovery can run when writing resumes. Recovery is per file: inspect the queue and rerun if an album was only partly completed. Do not delete state files to clear an interrupted job.

Copy mode rejects overlapping trees, symlinks, unrelated destination collisions, and changed owned outputs. It refuses to replace an existing copy with different audio; select a new destination in that case. The reserved .track-tagger- prefix marks temporary stages. An abandoned stage can be removed while the app is stopped. Different state directories do not coordinate writers, so do not run competing write processes against one music tree.

Cloud placeholders, zero-length files, and recognized partial downloads wait for availability. Pin cloud recordings locally before processing. Track Tagger verifies audio payload identity without decoding FLAC frames; that check cannot prove that a nonempty download is complete.

12. Command line quick reference

The desktop installer and ZIP include track-tagger.exe. On other platforms, build the Go command. Preview is the default for every processing command: omit all mode flags or use --dry-run explicitly. To change media, select either --write or --copy DEST; these mode flags are mutually exclusive. Use explicit --write for undo.

track-tagger scan SOURCE --dry-run
track-tagger scan SOURCE --json --plan PLAN.json
track-tagger serve SOURCE
track-tagger serve SOURCE --copy DEST
track-tagger watch SOURCE --write --poll
track-tagger apply PLAN.json --write
track-tagger undo JOB_ID
track-tagger undo JOB_ID --write

scan makes a one-time plan, serve opens the local review service, and watch observes new changes. apply reads a saved plan and revalidates it. Save plans outside music trees. A hand-edited JSON plan must explicitly set Reviewed to true and still pass evidence checks. undo JOB_ID previews restoration unless --write is supplied.

Use --state DIR for application storage outside source and destination trees. --settle defaults to 2m; --reconcile defaults to 5m. --poll observes network shares every 15 seconds. The server binds to localhost by default.

Remote browser access

Remote access requires --remote, a listening address, and a TRACK_TAGGER_TOKEN of at least 16 characters. Use any Basic Auth username and the token as the password. Set the token in the environment rather than a command argument. The examples below stay in Preview mode; choose Copy or Update originals only when you intend to write. Put remote access behind HTTPS or an encrypted private tunnel.

PowerShell:

$env:TRACK_TAGGER_TOKEN = 'replace-with-a-long-random-secret'
track-tagger serve SOURCE --remote --addr 0.0.0.0:8787

POSIX shell:

export TRACK_TAGGER_TOKEN='replace-with-a-long-random-secret'
track-tagger serve SOURCE --remote --addr 0.0.0.0:8787
