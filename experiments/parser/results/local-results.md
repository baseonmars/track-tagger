# Local and synthetic parser experiments

These are experiment results, not changes to the production parser. Local models were evaluated using source-only inputs on an Apple M2 Max with 64 GiB memory, llama.cpp commit `149f5641b931aaf33697d70f9abc90c3e5300247`, Qwen3 Q8 weights, 32,768-token context, no context shift and six CPU threads. Metal offload was verified; CPU measurements disable GPU, KV and operation offload. The final shared prompt requires source quotes and source note names. A deterministic wrapper reconciles filenames and requires review for missing or invalid evidence. The freeze and scoring records distinguish all requested cases, eligible labels and failed outputs.

The validation and common test results below use separate frozen source-reviewed labels. These labels are independent model-assisted source reviews, not human certification. The common 40 test inputs include 39 eligible labels and one disputed case; the disputed input is evaluated operationally but excluded from accuracy. Malformed, truncated and rejected requests remain in the accuracy denominator when the label is eligible. An accepted nonexact case is not by itself proof of a wrong mapping.

A diagnostic Qwen3 1.7B r1 run completed on the same validation 30 before the final prompt revision: 8 errors, 337/556 correct titles, 234/611 correct reconciled mappings, 2/30 exact, and no accepted cases; successful outputs required review and failures were counted separately. One additional 1.7B prediction completed before the reviewed validation labels were frozen due to an orchestration error. On shared exploratory synthetic40, 0.6B scored 0/154 titles by disc:track. All 106 emitted title-map keys were filenames rather than disc:track IDs; 16 emitted values exactly matched an expected title under a wrong filename key. Thus the score is not a count of correct title strings appearing anywhere. The wrapper held all 40 cases for review. The 1.7B candidate scored 24/154 keyed titles and 24/165 validated mappings, with 27 duplicate-identifier errors; its successful outputs required review and its 27 failures were counted separately. Both scored 0/40 exact and had no validated false-ready or incorrect accepted mappings.

The synthetic V1 set is frozen but has one known invalid conflicting-date label and an unrepresentative header that caused scanner review in every case. V2 is an explicitly baseline-informed exploratory revision with a frozen 5,000-case family-separated split; its generated labels are not independently reviewed. The scanner's V2 final scorer v3 rescoring produced 3,017/5,000 exact cases and 18,171/20,621 correct mappings; 1,054 incorrect accepted mapping fields include bracketed-duration differences requiring policy adjudication. These are generated-label-dependent measurements, not validated production defects.

A word, character and neighboring-line classifier trained on V2 generated labels scored 100% train, 95.21% validation and 94.91% test line accuracy on the separated synthetic families. Templates and labels are artificial; these are not real-note, safety or mapping metrics. Its fitted artifact is 570,495 bytes, SHA256 `67c28af89e587ed9a5e2aaeb3f7e23c1649b40a655ae144cb14a7d79df2a3ba7`; training and evaluation took 3.48s wall time with 298.9 MB peak RSS on this machine.

A separate real-note classifier used a posthoc source-only uploader-disjoint partition: 459/800 train and 144/200 validation cases were retained, with all 200 test cases kept. The known cross-split template family was excluded from train/validation. This does not prove all cross-uploader templates are unseen. Training used 7,184 cited positive lines from 457 retained train cases; two retained cases had genuine annotation failures. Validation used 2,711 cited lines from 140 reviewed cases; four retained cases were disputed. Among cited positive validation lines, accuracy was 98.045%, macro F1 0.9393, versus 82.995% for the title-majority class chosen solely from training.

The frozen model was evaluated once on 3,655 cited positive test lines from 197 reviewed cases; three disputed cases were excluded. Classification among cited positive test lines was 98.960% accurate, macro F1 0.9663, versus 84.405% for the training-selected title-majority baseline. Uncited lines are excluded rather than assigned a background label. These measurements cannot estimate false positives on ordinary or technical lines or establish whether the classifier could replace rule-based line detection. The partial 117-case training run was diagnostic and is not the final classifier. Final fitting took 9.71s wall, 26.69s user and 11.33s system CPU, with 372.7MB peak RSS under shared load; the model is 3,562,225 bytes, SHA256 `5495b7b3f5cc8b8872db9450730bcc102ea9951be7ed4fcec9b9a25d8d35318c`. On the same 3,655 cited test lines, three frozen-model feature-transform plus prediction batches took 0.302/0.322/0.314s wall and 0.302/0.322/0.313s process CPU, with 174.0MB process peak RSS. These timings exclude model loading and source rehydration, were measured under shared GPU quality-run load, and are not end-to-end parser timings.

A public replay validated all 1,200 rehydrated source-case identities and hashes, trained from frozen text-free line references, and reproduced the original train, validation and test confusion matrices. Retrained model bytes differed, so this establishes metric equality in the tested environment, not bit-identical model files. The published reference digest is trusted for selected-label semantics; source and context hashes check bytes and do not independently prove citation meaning. Training data, source notes, model artifacts, predictions and verbose server logs remain outside Git.

The optional derived Q4_K_M candidate used Qwen3-1.7B selected by pre-test validation title performance. It was converted from the official Qwen3-1.7B BF16 source revision `70d244cc86ccca08cf5af4e1e306ecf908b1ad5e`, after verifying both source shard hashes, using the pinned llama.cpp converter and quantizer; it was not requantized from Q8. The derived Q4 file is 1,282,439,616 bytes, SHA256 `cf7f7ce724f5d403b15a8f5763fc5fcafe0220fa202f34f879511e9675870bb9`. The official Q8 card names the same base-model family but does not establish an exact BF16 source revision or shard link. Both artifacts declare Qwen3 architecture, 28 blocks, embedding length 2048 and context 40960; comparison may still include source-revision or conversion differences, so it does not isolate a causal quantization effect. The GGUF parent-model lineage field describes ancestry, not the immediate download source.
